# ULX Demo And Documentation Workflow

## Use this skill when

- Adding a new component demo page
- Adding a new variation to an existing demo
- Updating demo source that drives documentation snippets
- Checking whether demo, snippet, and doc wiring still match

## Workflow

1. Start from the demo source under `ulx/src/demo/ulx-ember/app/components/Demo`.
2. Prefer existing repo scripts for scaffolding instead of hand-creating related files.
3. Use `ulx/package.json` as the source of truth for available helper scripts and entrypoints.
4. Keep the demo component, snippet output, and imports/features wiring aligned.
5. When a demo changes behavior or public usage, make sure the shown snippet still reflects the real example.
6. Avoid manual edits to autogenerated documentation output when the repo rules mark it as generated; prefer the approved workflow or source demos instead.
7. When a task touches routing, features, or nav metadata, verify the component still appears in the expected docs section.

## Script selection

- New component demo page: use the repo's `create:demo-page` workflow
- New demo variation for an existing component: use the repo's `add-variation` workflow
- Demo source changed and snippet output must match: use the snippet sync workflow

## Verification

1. Confirm the demo renders from `app/components/Demo/...`.
2. Confirm the snippet shown to users matches the demo source.
3. Confirm docs imports and feature entries still reference the right demo and snippet names.
4. Confirm the workflow respects repo rules about generated documentation trees.
